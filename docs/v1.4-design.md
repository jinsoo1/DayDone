# v1.4 설계 — 알림

> 2026-08-20 작성. 구현 전 설계 문서. 구현이 끝나면 핵심 결정을 CLAUDE.md에 반영하고 이 문서는 기록으로 남긴다.
> 대표 기능: **알림**. 동승: 큰 지출 예상 달 안내(주말·명절).
> 원칙: 다그치지 않는다(§13), 민감 권한 안 쓴다, 끄면 조용하다.

## 0. 권한 — "켜는 사람만" (핵심 결정)

Android 13+ 는 알림에 `POST_NOTIFICATIONS` 권한이 필요하다. 지금까지 **"권한 0개"** 를
1.1.0 공지·스토어 설명·홍보 포스트·1.3.0 공지에서 계속 내세워 왔으므로, 이 약속을
깨지 않는 형태로만 도입한다.

- **첫 실행 때 묻지 않는다.** 온보딩에 알림 권한 요청을 끼워 넣지 않는다.
- **설정에서 알림을 직접 켤 때만** 권한을 요청한다. 거부하면 스위치는 꺼진 채로 두고
  "설정에서 언제든 켤 수 있어요" 정도만 안내한다(설정 앱으로 강제 유도하지 않는다).
- 기본값은 **전부 off**. 아무것도 안 켜면 권한 요청이 없고 "권한 0개"가 사실로 유지된다.
- 문구: "알림을 처음 켤 때만 권한을 물어봐요. 안 켜면 권한은 0개 그대로예요."
- ⚠️ 스토어 문구를 "권한 0개" → **"켜지 않으면 권한 0개"** 로 바꿔야 한다.
  (listing.md · promo.md 5번 포스트 · 다음 공지)

## 1. 알림 5종

전부 개별 on/off. 하나도 안 켜면 알림 채널조차 만들지 않는다.

| # | 알림 | 시점 | 문구 |
|---|---|---|---|
| 1 | 아침 권장 금액 | 매일 아침(기본 8시) | "오늘은 32,000원까지 괜찮아요" / "이번 기간 12일 남았어요" |
| 2 | 저녁 기록 안내 | 오늘 지출이 0건일 때만, 저녁(기본 21시) | §2 참고 |
| 3 | 보류함 30일 | 보류 30일째 되는 날 아침 | "무선 이어폰, 30일이 지났어요" / "아직도 필요하면 그때 사요. 일단 아낀 돈에 넣어뒀어요" |
| 4 | 기간 결산 | 새 기간 첫날 아침 | "지난 기간 결산이 나왔어요" / "148,000원을 지켜냈어요. Day Done!" |
| 5 | 큰 지출 예상 달 | 기간 첫날 아침 | "이번 달엔 추석이 있어요" / "큰 지출이 예상되면 금고에 미리 나눠 담아두면 편해요" |

- 탭하면 각각: 오늘 탭 / 지출 입력 시트 / 보류함 / 결산 리포트 / 금고 탭.
- 같은 날 여러 개가 겹치면 **아침 알림은 하나로 합친다**(1+4+5 → 한 건).
  알림 세 개가 연달아 오면 그것만으로 잔소리가 된다.

### 왜 아침 알림이 위젯과 겹치지 않나

위젯은 **찾아봐야 보이고**, 알림은 **찾아오지 않아도 도착한다.** 위젯을 안 놓는 유저가
훨씬 많고, 하루의 시작에 기준선을 주는 것이 이 앱의 본질이라 역할이 다르다.

## 2. 저녁 기록 안내 (오늘 지출 0건일 때만)

목적은 독촉이 아니라 **정확도**다. 오늘 쓴 걸 안 넣으면 내일 권장 금액이 실제보다
크게 나와서, 앱이 틀린 숫자를 자신 있게 말하게 된다.

### 발송 조건 (전부 만족할 때만)

- 그 시점에 **오늘 날짜 지출이 0건**
- 알림이 켜져 있음
- 하루 한 번만

### ⚠️ 무지출 챌린지와의 충돌 — 반드시 처리

챌린지를 하는 사람에게 지출 0건은 **성공한 날**이다. 여기에 "지출 없으세요?" 를 보내면
축하해야 할 순간에 잔소리를 하는 셈이 된다.

- **챌린지 진행 중 + 오늘 무지출 성공** → 문구를 **축하로 전환**하고 입력 요청을 뺀다.
  "오늘 지갑이 쉬었어요 🎉 / 무지출 N일째, 잘하고 있어요"
- 그 외 → 아래 기본 문구. 다만 **안 쓴 사람도 자연스럽게 읽히도록** 쓴다.

### 기본 문구

> **오늘 기록이 아직 없어요**
> 쓴 게 있다면 지금 넣어두면 내일 금액이 정확해져요. 안 썼다면 그대로 두셔도 좋아요.

"왜 입력 안 했냐"가 아니라 "안 썼으면 그대로 두라"를 같은 문장에 담는다.
탭하면 지출 입력 시트가 바로 열린다(오늘 날짜 프리필).

## 3. 설정 UI

설정 탭에 "알림" 섹션. 스위치 5개 + 시각 선택.

- **시각은 칩 3개로.** 아침 7·8·9시 / 저녁 20·21·22시. 시간 피커는 과하다.
- 섹션 아래 🔒 한 줄: "알림을 처음 켤 때만 권한을 물어봐요. 안 켜면 권한은 0개 그대로예요."
- 저장은 DataStore(`NotificationSettingsDataSource`). Room 변경 없음.

## 4. 기술

- **WorkManager** 로 예약한다. Glance 가 이미 끌어와 새 의존성이 없고,
  v1.3 에서 넣은 R8 규칙(InputMerger 생성자 보존)이 그대로 유효하다.
- ⚠️ **정확 알람(`SCHEDULE_EXACT_ALARM`)은 쓰지 않는다.** 그건 진짜 민감 권한이다.
  아침 알림이 몇 분 늦는 것은 감수한다(Doze 에서 더 늦을 수 있음도 감수).
- 예약 방식: 다음 발송 시각까지 `initialDelay` 를 준 OneTimeWork → 발송 후 **스스로 다음 날을 재예약**.
  (`PeriodicWork` 는 최소 주기·정렬 문제로 "매일 8시"에 맞추기 어렵다)
- 부팅 후 재예약: `BOOT_COMPLETED` 수신 후 다시 건다.
  `RECEIVE_BOOT_COMPLETED` 는 민감 권한이 아니다.
- 알림 채널은 **하나**("하루 알림"). 종류별로 채널을 쪼개면 설정 화면이 시스템에서 어지러워진다.
- 알림 내용은 전부 기존 계산에서 파생 — `ObserveDailyBudgetUseCase`, 보류함, 결산 리포트.
  **새 계산을 만들지 않는다**(v1.3 에서 계산을 하나로 합친 이유가 여기서도 적용된다).

---

## 5. 안 하는 것

- **초과 경고 알림** ("오늘 권장을 넘겼어요") — 위젯에서 빨간 숫자를 뺀 것과 같은 이유.
  다그치는 순간 이 앱이 아니게 된다.
- 지출 입력 독촉(§2 는 0건일 때 하루 한 번, 안 썼으면 그대로 두라고 말한다 — 독촉과 다르다)
- 마케팅·재참여 유도 알림, 알림 뱃지, 소리·진동 강제(기본 무음 채널 중요도 DEFAULT)

## 6. 구현 순서

1. `NotificationSettingsDataSource`(DataStore) + 설정 탭 UI + 권한 요청 흐름
2. 알림 채널·표시 공통부(탭 시 화면 이동 포함)
3. WorkManager 예약/재예약 + 부팅 수신
4. 아침 알림(1) → 합치기 규칙(4·5 포함)
5. 저녁 기록 안내(2) — 챌린지 분기 포함
6. 보류함 30일(3)
7. 스토어·공지 문구에서 "권한 0개" → "켜지 않으면 권한 0개" 로 정정

## 7. 테스트

- 발송 조건: 오늘 지출 0건/1건, 챌린지 on+무지출, 챌린지 on+지출 있음
- 아침 합치기: 결산·명절이 같은 날 겹칠 때 한 건인지
- 보류함 30일: 경계(29일째/30일째), 이미 확정된 항목은 안 보냄
- 재예약: 발송 후 다음 날이 잡히는지, 시각 변경 시 다시 잡히는지
