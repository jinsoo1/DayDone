## 1. 살까 말까 (구매 결정 도우미) ⭐ 대표 기능

### 컨셉

점수·판정이 아니라 **결과를 보여준다**: "지금 사면 남은 기간 하루 권장이 32,000원 → 24,000원이 돼요."
앱은 사라/사지 마라를 말하지 않는다. 숫자가 스스로 말하게 하고, 결정은 유저가 한다. (§13: 압박 금지)

### 진입점

- **하단 중앙 `+` 시트에 "살까 말까?" 항목 추가** (지출/수익/저축·고정비/이번 달 예산 + 살까 말까).
- 오늘 탭 상주 카드는 만들지 않는다 — 오늘 탭은 처방 화면, 도구는 `+`가 집.

### 입력

- **품목명 + 금액** 두 칸 (품목명은 보류함 저장 때 의미가 생기므로 필수, placeholder "예: 무선 이어폰").
- 기존 입력 시트 스타일(internal 재사용) 그대로.

### 계산 (전부 read-only — 구조 충돌 없음)

**오늘 탭과 완전히 같은 소스**를 재사용한다. 숫자가 오늘 탭과 1원이라도 다르면 신뢰가 깨지므로,
`CalculateTodayDefenseLineUseCase`와 동일한 입력을 받아 P만 빼는 구조로.

```
R = 남은 순수 생활비 (월예산 + 추가수익 − 저축 − 고정비 − 지출합)
D = 남은 일수 (오늘 포함)
현재 하루 권장 A = R ÷ D      ← 오늘 탭 숫자와 반드시 일치
구매 후 하루 권장 B = (R − P) ÷ D
```

결과는 4단계 프레임 (경계값은 구현 시 튜닝, 초안):

| 상태 | 조건(초안) | 헤드라인 (§13 톤 — 판정 없이 사실+뉘앙스만) |
|---|---|---|
| 거의 무변화 | 권장 감소 < 5% | "이 정도는 티도 잘 안 나요. 사도 괜찮아요." |
| 여유 | B ≥ A의 70% | "사도 괜찮아요. 남은 예산 안에서 소화돼요." |
| 빠듯 | 0 ≤ B < A의 70% | "살 수는 있어요. 다만 남은 {D}일이 조금 빠듯해져요. 잠깐 보류해볼까요?" |
| 불가 | R − P < 0 | "이번 기간 생활비로는 어려워요. 금고에서 몇 달에 나눠 준비하면 마음 편히 살 수 있어요." |

- **빠듯도 "살 수는 있어요"로 시작** — 앱이 말리는 게 아니라 트레이드오프를 보여줄 뿐.
- 핵심 비교는 하나만: "오늘 기준 하루 권장 {A}원 → 사면 {B}원 (남은 {D}일 동안)" + 보조 줄 "남은 생활비 {R} → {R−P}". 숫자는 이 4개가 전부 — 더 넣으면 시뮬레이션이 아니라 분석이 된다.
- 입력 버튼 라벨: "계산하기"가 아니라 **"얼마나 달라지는지 보기"** (기능의 본질을 버튼이 말함).

### 결과 화면의 선택지 (같은 시트에서 확장, 화면 이동 없이 10초 안에 끝나는 도구)

- 여유/빠듯: **[보류할게요] [살게요]** 동일 무게(tonal) 나란히 — 어느 쪽도 밀지 않음. 아래 텍스트 버튼 "닫기".
- 불가: **[금고에 준비하기]**가 primary — 유일하게 방향을 제시하는 상태. 못 사는 게 아니라 "사는 방법"을 알려주는 프레임. **[그래도 살게요]**를 반드시 남긴다(앱은 금지하지 않음).
- **[살게요]** → 기존 지출 입력 시트에 품목명·금액·오늘 날짜 프리필 → 저장하면 일반 지출(재분배는 기존 로직). 새 저장 경로 없음.
- **[보류할게요]** → 보류함 저장, 확인 문구 "보류함에 넣어뒀어요. 30일 뒤에도 생각나면 그때 사요."
- **[금고에 준비하기]** → 준비 항목 추가 시트 프리필(제목=품목명, 총액=가격, **목표월=3개월 뒤 기본값**, 수정 가능). 이후 기존 금고 흐름 100% 재사용 — 금고 불변식 그대로.

### 엣지 케이스

| 케이스 | 처리 |
|---|---|
| 이미 예산 초과 (R ≤ 0) | 불가 상태. 문구 변형: "이번 기간 생활비가 이미 다 쓰였어요. 금고에서 나눠 준비하면 다음 기간이 편해져요." |
| 기간 마지막 날 (D=1) | 정상 계산 — "오늘 하루 권장이 32,000원 → 2,000원이 돼요" |
| 가격 = 남은 생활비 전액 | B=0원, 빠듯 상태. "사면 남은 {D}일 권장이 0원이 돼요" — 사실만 |
| 금액 0/미입력 | 버튼 비활성 |
| 보류함 항목 다시 열기 | 30일 전이라도 항목 탭 → 오늘 기준으로 재계산된 같은 결과 화면 → 살게요/안 살래요 |

### UseCase & 테스트

- `EvaluatePurchaseUseCase(pureBudgetLeft, remainingDays, price)` → `PurchaseEvaluation(currentDaily, afterDaily, state)` — **순수 함수**.
- 유닛 테스트: 4개 상태 경계값(5%/70%/0), D=1, R=0, R<0, P=R 정확히 일치.

### 안 하는 것 (전부 "앱이 모르는 걸 아는 척"하게 되는 방향)

카테고리별 판단 · 과거 소비 이력 참조 · 점수/등급 · 구매 후 만족도 추적 · 알림.

## 2. 소비 보류함

### 컨셉

"말까"의 목적지. **30일 룰 + 아낀 돈 집계** — 사라고 밀지 않고 안 산 걸 축하한다.

> 용어 결정: "지켜낸 돈"이 아니라 **"아낀 돈"** — 결산 리포트가 "지켜냈어요"를 다른 뜻(예산 안 넘김)으로 이미 쓰고 있어 어휘를 분리한다(리포트=지킴, 보류함=아낌). "지키다"는 외부 위협 뉘앙스라 자발적 결정엔 부자연스럽기도.

### 데이터 (DB v6 → v7, 유일한 마이그레이션)

```
HeldPurchaseEntity (held_purchases)
- id: Long PK autoGenerate
- title: String
- amount: Long
- heldAt: String("YYYY-MM-DD")      // 보류한 날
- status: String                     // HELD / PASSED(안 삼 → 아낀 돈) / BOUGHT(결국 삼)
- resolvedAt: String?                // 상태 확정일
- createdAt: Long
```

- 기존 테이블·기간·이월·anchorMonth 전혀 건드리지 않음.
- **백업**: `BackupDao`/`BackupRepositoryImpl` 양쪽에 필드 추가 (CLAUDE.md 규칙). 새 배열 키 추가는 하위 호환(구버전은 무시)이라 `BACKUP_VERSION=1` 유지.
- **초기화**: `clearAllTables()`가 자동 포함. **엑셀 내보내기엔 미포함**(지출 이력이 아님).

### 30일 룰 (알림 없음 — "권한 없음" 포지션 유지)

- 보류 중 항목은 "D+{n}일째 보류 중" 표시.
- **30일 경과 시 자동으로 PASSED 전환** + 아낀 돈에 합산. 항목엔 "30일 동안 안 샀어요 — 아낀 돈이 됐어요" 기록. 전환 직후 카드: "30일이 지났어요. 아직도 필요하면 그때 사요 — 일단 아낀 돈에 넣어뒀어요." + [그래도 샀어요].
  - 자동인 이유: "딱 한 번 묻고 끝" 원칙에서 무응답이 기본값이 되면 마찰 0. 나중에 정말 사면 그냥 지출로 입력하면 되고, 항목의 **[그래도 샀어요]** 버튼으로 BOUGHT 전환도 가능(아낀 돈에서 제외).
  - 전환 시점 판정은 조회 시 파생(`heldAt + 30 ≤ today`) — 백그라운드 작업 불필요.
- 30일 전이라도 항목에서 [지금 살게요 → 지출 프리필] / [안 살래요 → PASSED] 즉시 확정 가능.

### 보류함 화면 & 진입

- 별도 라우트(`HeldPurchasesRoute`, ChallengeHistory 패턴).
- 구성: ① 헤더 "보류함으로 아낀 돈 {N}원" + 서브 "안 사길 잘한 것들이 쌓이고 있어요" (PASSED 합계) ② 보류 중 리스트(D+n일째 · 남은 날 + 진행 바, [지금 살게요][안 살래요]) ③ 지난 기록 — 안 삼(초록): "30일 동안 안 샀어요 — 아낀 돈이 됐어요" / "{n}일 만에 안 사기로 했어요", 삼(중립 회색): "{n}일 고민하고 샀어요" (§13: 산 것도 실패가 아니라 고민한 결정).
- **진입: 금고 탭 하단 카드** "보류함 — 아낀 돈 N원 · 보류 중 N건" (금고=모아둔 돈, 보류함=아낀 돈: 정서 일치. 금고 값 파생 불변식과는 무관한 별도 섹션). 30일 도래 항목이 있으면 카드에 점 뱃지.
- 오늘 탭 배너는 쓰지 않는다 — 이미 결산·가입 전 지출 배너가 있어 과밀.

### UseCase

- `HoldPurchaseUseCase(title, amount)` / `ObserveHeldPurchasesUseCase()` (30일 자동 전환 파생 포함) / `ResolveHeldPurchaseUseCase(id, bought|passed)`.

## 3. 리포트 지난 기간 대비

- `ReportViewModel`이 **이전 기간**의 지출·예산도 함께 조회 → `BuildMonthlyReportUseCase`에 `previous: PeriodSnapshot?(총지출, 순수생활비, 무지출일수, 하루평균)` 전달.
- 표시(과하지 않게 2곳만):
  - 페이스 카드 아래 한 줄: "지난 기간 같은 시점보다 {N}원 덜/더 썼어요" — **같은 dayIndex까지의 지출끼리 비교**(기간 전체와 비교하면 진행 중엔 항상 "덜 씀"으로 보이는 왜곡 방지).
  - 미니 지표에 △ 표기: 하루 평균·무지출 일수 (지난 기간 최종값 대비).
- 이전 기간이 없거나(첫 기간) 이전 기간이 부분 기록(trackingStartDate 존재)이면 **비교 자체를 숨긴다** — 어긋난 비교보다 없는 게 §13.
- 저장 없음, 전부 파생 — 구조 충돌 없음.
