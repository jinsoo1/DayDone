## 0. 선행 작업 — 권장 금액 계산 단일화 (⚠️ 위젯보다 먼저)

지금 "남은 순수 생활비 ÷ 남은 일수"가 **두 군데**에 있다.

| 위치 | 쓰는 곳 |
|---|---|
| `TodayViewModel.loadToday` | 오늘 탭, 살까 말까(오늘 탭 경유) |
| `ObservePureBudgetUseCase` | 보류함 재계산 |

여기에 위젯과 "내일부터"까지 붙으면 **사본이 4개**가 된다. 숫자가 1원이라도 어긋나면
앱 전체의 신뢰가 깨지는 값이라, 위젯을 붙이기 **전에** 하나로 합친다.
(붙인 뒤에 하면 리팩터링이 아니라 버그 추적이 된다.)

**방법**: `ObservePureBudgetUseCase`를 확장해 권장 금액까지 담은 스냅샷을 돌려주고,
`TodayViewModel`이 자체 계산 대신 이걸 쓰게 바꾼다.

```
DailyBudgetSnapshot(
  period, remainingPureBudget, remainingDays,
  todayRecommended,      // 오늘 권장 (오늘 지출 차감 전)
  todaySpent, todayLeft, // 오늘 남은 금액 / 초과 시 음수
  tomorrowRecommended    // §2
)
```

- 기존 `CalculateTodayDefenseLineUseCase`는 순수 함수라 그대로 재사용(테스트 51개 보존).
- 오늘 탭 숫자가 리팩터링 전후로 동일한지 확인하고 넘어간다.

## 1. 오늘 카드 "내일부터" 한 줄 (동승)

### 계산

```
내일 권장 = (남은 순수 생활비 − 오늘 지출) ÷ (남은 일수 − 1)
```

- 오늘이 기간 **마지막 날**이면(남은 일수 1) 나눌 날이 없다 → 금액 대신
  **"내일부터 · 새 기간이 시작돼요"**. 억지로 0원을 지어내지 않으면서,
  기간이 끝나간다는 사실을 알려 다음 기간을 기대하게 만든다.
  (다음 기간 예산은 아직 모르므로 금액은 쓰지 않는다.)
- 남은 예산이 음수여도 그대로 보여준다(음수 권장은 기존 재분배 규칙과 동일).

### 표시

기존 카드 맨 아래에 얇은 구분선 + 한 줄. 좌 "내일부터" / 우 금액.

- **정상**: "내일부터 31,400원" — 내일은 좀 더 여유 있다는 계획 감각.
- **초과**: 같은 줄이 안심 문구를 숫자로 증명한다. "5,400원 초과" 아래에
  "내일부터 31,400원"이 붙어야 "괜찮아요, 남은 날에 다시 나눠볼게요"가 말로 끝나지 않는다.
- 카드가 이미 빽빽하므로 **한 줄만.** 설명 문구를 덧붙이지 않는다.

## 2. 홈 위젯 (대표)

### 기술

- **Glance**(`androidx.glance:glance-appwidget`) — Compose 문법이라 기존 코드와 결이 맞다.
- 데이터는 `provideGlance` 안에서 §0의 스냅샷을 **1회 읽기**(Flow 구독 아님).
- 색상은 Glance `ColorProviders`로 라이트/다크를 함께 정의. 앱 팔레트 재사용
  (`TossBlue` #3182F6, `TossBlueContainer` #E8F1FF, `GrayText` #8B95A1).
  ⚠️ 위젯은 런처 위에 놓이므로 `Color(0xFF…)` 하드코딩 금지 규칙이 앱보다 더 중요하다.

### 크기와 내용

| 크기 | 내용 |
|---|---|
| **2×2** | 라벨 "오늘 남은 금액" · 금액(큰 숫자) · 진행 바 · "N일 남음" |
| **4×2** | 위 + 기간 표시 · "내일 N원" · "오늘 권장 32,000원 중 7,400원 씀" |

- **2×2에는 내일 금액을 넣지 않는다.** 위젯의 미덕은 "숫자 하나"다.
  정보를 더 원하는 사람이 4×2를 고른다.

### 초과 상태 — 위젯은 빨간 숫자를 쓰지 않는다 (결정)

앱 안에서는 초과를 빨간색으로 보여주지만, **홈 화면에 빨간 숫자가 상주하는 건 §13 톤과 어긋난다.**
하루 종일 잔소리를 띄워두는 셈이 된다.

| 상태 | 위젯 표시 |
|---|---|
| 정상 | "오늘 남은 금액" + 남은 금액 (파랑) |
| 초과 | "오늘은 조금 넘겼어요" + **내일 권장 금액**을 큰 숫자로 (파랑, 2×2도 포함) |

초과 시에는 위젯이 **미래를 보여준다.** 오늘의 실패가 아니라 내일의 기준을 띄우는 것이
이 앱의 태도이고, 위젯에서 "내일 금액"이 가장 쓸모 있는 순간이기도 하다.

### 갱신 전략 (권한 0개 유지)

1. **데이터 변경 시 즉시** — 지출/수익/예산/예정 차감 저장 후 `updateAll()` 호출.
   지출을 넣었는데 위젯이 그대로면 신뢰가 깨진다. 가장 중요한 경로.
2. **자정 넘김** — `updatePeriodMillis` 30분(최소값, 권한 불필요)으로 바닥을 깔고,
   `provideGlance`에서 매번 오늘 날짜를 다시 계산한다. 최대 30분 지연은 허용.
   - `ACTION_DATE_CHANGED` 수신으로 즉시 갱신이 되는지는 **구현 시 확인**
     (Android 8+ 암시적 브로드캐스트 제한 대상인지 검증 필요). 되면 보조로 추가.
   - ⚠️ 정확 알람(`SCHEDULE_EXACT_ALARM`)은 **쓰지 않는다** — 권한 0개 원칙 위반.
3. **앱에서 복귀 시** — `TodayViewModel.onResumed()`의 날짜 변경 감지에 위젯 갱신을 함께 건다.

### 동작

- 위젯 탭 → 앱 **오늘 탭**으로. 딥링크로 살까 말까 등을 여는 건 v1.3 범위 밖.
- 온보딩 전(예산 미설정)이면 "예산을 먼저 설정해 주세요" + 탭하면 앱 열기.
- 위젯 선택기용 미리보기 이미지(`previewImage`) 준비 — 첫인상이라 데모 숫자로 정성껏.

## 3. 범위 밖 (v1.3에서 안 함)

- 위젯에서 바로 지출 입력(액션 버튼) — 입력은 앱에서. 위젯은 "보는 것"에 집중.
- 잠금화면 위젯, 다양한 테마/색상 선택, 위젯 설정 화면(Configuration Activity).
- 알림(v1.4), 주말·명절 안내(v1.4~1.5).

## 4. 구현 순서

1. **§0 계산 단일화** + 오늘 탭 숫자 동일성 확인 (여기부터 시작)
2. "내일부터" 한 줄 (§1) — 작고, 위젯이 쓸 값을 먼저 만들어 둠
3. Glance 위젯 2×2 (§2) — 정상 상태만
4. 4×2 + 초과 상태 분기
5. 갱신 경로 3종 연결 + 실기기 자정 테스트
6. 미리보기 이미지 · 버전/공지 · 스토어 스크린샷(위젯 놓인 홈 화면)
